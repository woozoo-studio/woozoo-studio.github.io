04 / ROS2 / 관제 연동

관제 화면에서 로봇 위치가 점프하듯 표시되는 문제

문제
실제 로봇은 연속적으로 이동했지만, 관제 화면에서는 위치가 한 지점에서 다음 지점으로 점프하듯 표시됐습니다. 관제용 위치 갱신이 amcl_pose 메시지 수신에 종속되어 있어, 이동 중 위치 변화가 화면에 제때 반영되지 않았습니다.
판단·구현
관제용 위치 발행을 amcl_pose 수신 흐름과 분리했습니다. TF의 map → base_footprint 변환에서 위치·방향을 읽어 PoseStamped 형식의 logitle_pose 토픽으로 발행하는 ROS2 노드를 작성하고, Zenoh 브리지와 FMS의 전달·구독 설정을 맞췄습니다.
확인한 결과
AMCL 메시지 수신과 별도로 관제용 위치를 발행하도록 구성했습니다. FMS가 Zenoh 브리지로 중계된 로봇별 /{robot_id}/logitle_pose를 구독해 지도 위치를 갱신하도록 연동했습니다.
  1. 01TF 위치·방향 조회
  2. 02logitle_pose 발행
  3. 03Zenoh 브리지 중계
  4. 04FMS 구독·지도 표시

05 / KEV-MAPF / 경로 계획

모델의 판단과 실행 전 검증을 나눠 교통조정

요구사항
여러 AMR의 경로가 공유 구간에서 겹칠 때 통과 순서, 대기 위치와 우회 행동을 조정해야 했습니다.
판단·구현
PBS의 우선순위 개념을 참고했습니다. KEV 점수로 계획의 우선순위를 정하고, 코드는 충돌 구역과 대기 후보를 검사하며 KEV의 양보 행동·우회 경로 판단을 FMS 실행에 연결했습니다.
구현 결과
마주 오는 로봇 중 한 대가 대기하고 다른 한 대가 먼저 통과하는 동작을 실기체에서 확인했습니다. PBS의 우선순위 개념을 참고한 KEV 응용 구현이며, PBS 전체 탐색이나 모델 자체 학습과 구분합니다.
  1. 01공유 구간 확인
  2. 02KEV 우선순위·행동
  3. 03경로·점유·예약 검사
  4. 04FMS 실행

실기체 확인 범위: 마주 오는 로봇의 대기·우선 통과. 우회·세 대 동시 이동의 성공률은 별도로 제시하지 않습니다.

06 / MQTT / 시스템 통합

MQTT 도킹 센서 수신 처리와 관제 상태 연동

요구사항
도킹 스테이션의 리미트 스위치가 ESP32 보드에 연결되어 있었습니다. ESP32에서 MQTT로 발행한 스위치 접촉 상태를 관제에서 수신하고, 스테이션별 도킹 상태에 반영해야 했습니다.
판단·구현
ESP32에서 발행한 리미트 스위치 접촉 상태를 수신하도록 mqtt_manager.py의 토픽 구독·메시지 처리 코드를 작성했습니다. dock/station/+/status 메시지의 JSON을 해석하고 스테이션 번호와 접촉 상태를 확인해 FMS에 전달했습니다.
구현 결과
스테이션별 접촉 상태를 관제에서 활용할 수 있도록 연동했습니다. 도킹 완료 처리에서는 Action 결과와 접촉 신호를 함께 확인하며, 도킹 완료 상태는 실제 전력 충전과 구분합니다.
  1. 01리미트 스위치 → ESP32
  2. 02MQTT 접촉 상태 발행
  3. 03토픽 구독·수신 처리
  4. 04FMS 도킹 상태 반영
