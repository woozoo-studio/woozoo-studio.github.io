04 / IMPLEMENTATION

주요 구현

04.01

Nav2 기반 AMR 자율주행

FMS가 전달한 목표와 경유점을 따라 이동하도록 Nav2 주행을 구성했습니다. TF·EKF와 Behavior Tree 설정을 함께 다루고 실기체에서 주행 동작을 확인했습니다.

  1. 01목표·경유점 수신
  2. 02Nav2 경로 생성·추종
  3. 03위치·방향 갱신
  4. 04이송·도착 상태 연동
04.02

다중 로봇 대기·우선 통과

공유 경로에서 로봇의 통과 순서와 대기 행동을 조정하는 KEV-MAPF 응용 로직을 구현했습니다. 실기체 시연에서는 마주 오는 두 로봇 중 한 대가 대기하고 다른 한 대가 먼저 통과하는 동작을 확인했습니다.

  1. 01공유 구간 확인
  2. 02KEV 우선순위·행동 판단
  3. 03경로·점유 조건 검사
  4. 04대기·통과 실행
04.03

로봇 위치 발행·관제 지도 연동

지도 기준 로봇의 위치·방향을 PoseStamped 토픽으로 발행하고, Zenoh 브리지를 거쳐 FMS 지도에 반영하도록 연결했습니다.

  1. 01TF 위치·방향 조회
  2. 02logitle_pose 발행
  3. 03Zenoh 브리지 중계
  4. 04FMS 구독·지도 표시
04.04

MQTT 도킹 접촉 상태 연동

ESP32에 연결된 리미트 스위치의 접촉 상태를 MQTT로 수신했습니다. 스테이션별 상태를 구분해 관제에 전달하고 도킹 완료 판단에 활용하도록 연동했습니다.

  1. 01리미트 스위치 → ESP32
  2. 02MQTT 접촉 상태 발행
  3. 03스테이션별 메시지 수신
  4. 04FMS 도킹 상태 반영

05 / PROBLEM SOLVING

문제 해결

05.01

관제 화면에서 로봇 위치가 점프하듯 표시되는 문제

문제
실제 로봇은 연속적으로 이동했지만, 관제 화면에서는 위치가 한 지점에서 다음 지점으로 점프하듯 표시됐습니다. 관제 위치 갱신이 amcl_pose 메시지 수신 시점에 묶여 있었습니다.
해결 과정
AMCL 메시지 수신과 관제용 위치 발행을 분리했습니다. TF의 map → base_footprint에서 위치·방향을 읽어 타이머 주기로 logitle_pose를 발행하는 ROS2 노드를 작성하고, Zenoh 브리지와 FMS의 전달·구독 설정을 맞췄습니다.
결과
AMCL 메시지 수신을 기다리는 방식에서 벗어나, 로봇별 위치 토픽을 별도 주기로 발행하고 관제 지도에서 구독하도록 연동했습니다.
05.02

이미 통과한 경유점으로 되돌아가는 문제

문제
NavigateThroughPoses로 전환한 뒤 로봇이 이미 통과한 중간 경유점으로 되돌아가는 왕복 현상이 발생했습니다.
해결 과정
RViz와 Behavior Tree 흐름으로 경유점 통과 판정과 남은 목표 목록 처리를 확인했습니다. 당시 시험에서 RemovePassedGoals 반경을 0.03m에서 0.06m로 조정하고, 경유점 확인은 3Hz·경로 재계산은 1Hz로 나눠 처리했습니다.
결과
수정한 Behavior Tree를 적용한 뒤 실기체에서 해당 왕복 현상이 해소되는 것을 확인했습니다.
05.03

공유 구간에서 겹치는 로봇 경로

문제
여러 로봇의 이동 경로가 공유 구간에서 겹쳐 통과 순서와 대기 위치를 정해야 했습니다. 선택한 행동을 실행할 수 있는지 경로·점유 조건도 함께 확인해야 했습니다.
해결 과정
PBS의 우선순위 개념을 참고해 KEV의 우선순위·행동 판단을 활용했습니다. 실행 전 경로·점유·예약 조건은 코드에서 확인하도록 나누고, 확인한 행동을 FMS의 대기·통과 처리에 연결했습니다.
결과
실기체에서 마주 오는 두 로봇 중 한 대가 대기하고 다른 한 대가 먼저 통과하는 동작을 확인했습니다.
