01 / AMR · 관제 연동

관제 위치 발행 분리

문제
관제 화면의 위치 갱신을 amcl_pose 메시지 수신에 의존해야 하는지 검토했습니다. 기존 구조에서는 AMCL 메시지를 받을 때 위치를 갱신했습니다.
해결
TF의 map → base_footprint 변환에서 로봇 위치를 읽어 관제용 토픽으로 발행하는 별도 ROS2 노드를 작성했습니다.
결과
AMCL·오도메트리 기반 TF를 활용해 관제용 위치 발행을 AMCL 메시지 수신과 분리하고, FMS의 지도 표시에 연동했습니다.
02 / 앱 제어 이동형 로봇팔

내부 Flash에 티칭 저장

문제
전원이 꺼져도 티칭 데이터를 유지해야 했습니다. 별도 EEPROM을 추가하는 방법 외에 보드 내부 Flash를 활용할 수 있는지 검토했습니다.
해결
마지막 128KiB(Sector 7)를 데이터용으로 확보하고 프로그램 저장 영역을 384KiB로 제한했습니다. 프로그램과 티칭 데이터가 서로의 영역을 덮어쓰지 않도록 구성했습니다.
결과
RAM에 모은 데이터를 Flash에 기록·검증하고 부팅 시 불러오도록 구현했습니다. 별도 EEPROM 없이 12개 시퀀스와 시퀀스당 최대 30 Waypoint를 저장합니다.
03 / 비전 · 학습 데이터

검출·포즈 라벨 형식 통합

문제
사람은 11개 키포인트로 자세를 학습하지만, 화재·무기 검출 데이터에는 바운딩 박스만 있어 동일한 Pose 학습 형식으로 사용할 수 없었습니다.
해결
화재·무기의 바운딩 박스 중심점을 키포인트 1개로 넣고 나머지 10개를 더미 처리해, 모델이 요구하는 11포인트 라벨 구조에 맞췄습니다.
결과
인체 Pose 라벨과 비인체 객체의 검출 라벨을 동일한 학습 형식으로 통합했습니다. 비인체 객체의 중심점은 라벨 호환을 위한 표현으로 사용했습니다.
03 / 비전 · 주행 제어

전진·후진 PID 보정

문제
전진·후진에서 동일한 모터 보정 부호를 사용하면 방향 보정이 반대로 작용할 수 있어, 주행 방향별 처리가 필요했습니다.
해결
IMU의 Yaw를 이용해 PID 보정값을 계산하고, 후진 시에는 전진과 반대로 좌우 모터의 PWM 보정 부호를 적용했습니다.
구현
주행 방향에 맞게 보정 로직을 분리하고, 적분 누적과 모터 출력에 상하한을 적용해 제어값이 범위를 벗어나지 않도록 구성했습니다.
